# SPEC-FULL - Especificação Funcional e Integração de APIs (Frontend Angular + Python BFF)

## 1. Visão Geral do Sistema
O sistema resolve a desorganização financeira eliminando o preenchimento manual de planilhas no Excel. O usuário pode inputar gastos manualmente ou fazer upload de faturas de cartão em PDF. O sistema faz OCR, identifica automaticamente o cartão emissor, realiza a **deduplicação e o rastreamento histórico de compras parceladas** (retornando sempre o valor da parcela, o número da parcela atual e a quantidade total de parcelas), permite a revisão interativa das transações e compila tudo em tabelas responsivas, dashboards, gráficos de linha do tempo e relatórios PDF.

---

## 2. Modelo de Dados Unificado

### Entidade: Gasto
- `id`: string (UUID)
- `gastoPaiId`: string (UUID, opcional) — *Vínculo de lançamentos mensais da mesma compra parcelada.*
- `data`: string (ISO 8601 - YYYY-MM-DD)
- `cartaoId`: string (UUID, Foreign Key)
- `categoria`: string (ex: "Eletrônicos", "Alimentação")
- `descricao`: string (ex: "Notebook")
- `valorParcela`: decimal (valor unitário da parcela no mês)
- `tipo`: enum ("normal", "parcelado", "fixo")
- `parcelaAtual`: integer (ex: 3)
- `totalParcelas`: integer (ex: 10)
- `origem`: enum ("manual", "fatura")
- `observacao`: string (opcional)

---

## 3. Especificação dos Endpoints e Contratos de Retorno (BFF Python -> Angular)

### 3.1. Requisito de Mapeamento Obrigatório de Parcelas
Para **qualquer listagem de gastos ou itens extraídos de fatura**, o payload de retorno do Python BFF para o Angular DEVE conter explicitamente a estrutura de parcelamento:
- `descricao`: Nome do item (ex: "Notebook")
- `valorParcela`: Valor cobrado no mês (ex: `250.00`)
- `parcelaAtual`: Número da parcela do mês consultado (ex: `3`)
- `totalParcelas`: Quantidade total de parcelas (ex: `10`)
